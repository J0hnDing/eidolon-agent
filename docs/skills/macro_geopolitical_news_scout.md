# Macro / Geopolitical News Scout

`macro_geopolitical_news_scout` is an installed `function` skill called by `weekly_report_service` on its weekly schedule. It has no schedule, Notion access, or filesystem permission. Runtime and integration reviews remain required. The function receives the previous report, seen release IDs and URLs, and last successful fetch time from its caller. It returns the selected report content, newly seen IDs and URLs, candidate count, fetch time, and source failures. The existing per-skill Codex model setting applies.

Each run fetches bounded recent official RSS/Atom releases from the [Federal Reserve](https://www.federalreserve.gov/feeds/feeds.htm), [BLS](https://www.bls.gov/feed/), [BEA](https://www.bea.gov/resources/for-developers), [Statistics Canada](https://www.statcan.gc.ca/en/sc/rss), [Bank of Canada](https://www.bankofcanada.ca/rss-feeds/), [ECB](https://www.ecb.europa.eu/home/html/rss.en.html), and [EIA](https://www.eia.gov/tools/rssfeeds/). Configured FRED, BLS, BEA, and EIA API keys allow corresponding trusted backend integration operations to add keyed release or series evidence. BLS, BEA, and EIA public feeds still work without keys; the other keyless feeds need no Settings setup. The single Codex call may use live web search for major geopolitical and financial news, OFAC/Treasury sanctions, trade and export controls, and source verification. [OFAC retired its RSS feed](https://ofac.treasury.gov/recent-actions/20250206), so it is covered through that search.

The function deterministically removes old, previously seen, duplicate, invalid, and excess feed/API candidates before analysis. Keyed series observations are explicitly labeled as observation periods with no claimed publication date; the model must corroborate any newly released data against a dated release. It includes the prior report and optional Atlas goals, projects, and interests as context. Codex selects zero to eight material developments, each with a concise event, significance, delta from the previous report, next thing to watch, and source URLs. It also writes a short overall macro picture and at most four important upcoming catalysts. Routine or repetitive news should result in no selected developments.

The weekly service builds native `Macro` Notion blocks from the validated function output. Its own `./cache/macro_geopolitical_news_scout.json` keeps the previous report, up to 5,000 seen release IDs/URLs, and the last successful fetch timestamp. It advances only after Notion accepts the report. A failed or unavailable optional source is listed in the function output while remaining sources continue; if every fetch fails, the function fails. The scout does not cluster events or maintain a knowledge graph. A crash after Notion creates a report but before the service cache update can leave a duplicate on the next run.
